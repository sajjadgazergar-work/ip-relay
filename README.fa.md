# رله پروکسی خروجی // ip-relay

**هر endpoint سازگار با OpenAI که محدودیت سهمیه بر اساس آدرس IP دارد را به یک استخر پروکسی چرخان با کانکارنسی بالا تبدیل کنید.**

[English Version](README.md) · [بنچمارک](BENCHMARK.md) · [اسکرین‌شات داشبورد](https://raw.githubusercontent.com/sajjadgazergar-work/ip-relay/main/docs/dashboard.png)

---

رله `ip-relay` به عنوان یک لایه میانی بین برنامه‌های هوش مصنوعی شما و هر ارائه‌دهنده API سازگار با OpenAI قرار می‌گیرد که محدودیت‌ها یا سهمیه رایگان خود را **بر اساس آدرس IP** اعمال می‌کند.

به جای برخورد با خطای `429 Too Many Requests` بعد از اتمام سهمیه تک IP سرور خود، `ip-relay` درخواست‌ها را به‌طور پویا از بین استخر چرخان از کانال‌های پروکسی فعال (HTTP/S, SOCKS4/5, Webshare) عبور می‌دهد. هر درخواست از یک IP تمیز خروجی می‌گیرد که سهمیه مستقل خود را دارد.

![داشبورد](https://raw.githubusercontent.com/sajjadgazergar-work/ip-relay/main/docs/dashboard.png)

> ⚠️ **توجه**: این ابزار صرفاً برای چرخش درخواست‌ها بین مسیرهای خروجی پروکسی جهت جلوگیری از اتمام سهمیه نرخ مصرف (Rate Limit) روی تک IP طراحی شده است. لطفاً پیش از استفاده، قوانین سرویس‌دهنده بالادست را مطالعه کرده و با آن سازگار باشید.

---

## ⚡ این ابزار چه مشکلی را حل می‌کند؟

| سناریو | بدون ip-relay | با ip-relay |
|---|---|---|
| **IP خروجی** | تمام درخواست‌ها از تک IP سرور شما عبور می‌کنند | درخواست‌ها بین **بیش از ۴۰ پروکسی فعال** می‌چرخند |
| **محدودیت سهمیه** | بعد از N درخواست خطای ۴۲۹ (تمام شدن سهمیه) می‌دهد | هر مسیر پروکسی سهمیه ایزوله‌شده خود را دارد |
| **زمان خرابی** | باید تا ۲۴ ساعت برای ریست سهمیه IP سرور صبر کنید | **failover خودکار**: پروکسی‌های سوخته بلافاصله بای‌پس می‌شوند |
| **سازگاری پروتکل** | محدود به قالب صلب یک سرویس‌دهنده | سازگار با **OpenAI API** و **Anthropic (`/v1/messages`)** |

## ✨ امکانات برجسته

- **🌐 مستقل از ارائه‌دهنده (Provider Agnostic)**: سازگاری کامل با `opencode.ai/zen/v1`، Groq، SambaNova، Together، DeepSeek، یا هر endpoint سازگار با OpenAI.
- **🔄 بازنشانی شفاف حین درخواست (Transparent Failover)**: در صورت خرابی یا دریافت خطای ۴۲۹ در میانه درخواست، رله بدون قطع ارتباط کلاینت، درخواست را در میلی‌ثانیه روی سریع‌ترین پروکسی بعدی تکرار می‌کند.
- **⚡ سیستم رتبه‌بندی امتیاز و زمان تاخیر (EWMA)**: پیگیری هوشمند سرعت و نرخ موفقیت هر مسیر پروکسی. پروکسی‌های سریع‌تر به‌طور خودکار اولویت بالاتری می‌گیرند.
- **🔑 ادغام چند اکانت Webshare**: امکان چسباندن چندین توکن API از اکانت‌های مختلف Webshare (به‌صورت خط به خط، با کاما یا سمیکالن) جهت تلفیق پروکسی‌های رایگان یا تجاری در یک استخر.
- **🤖 گیت‌وی پروتکل Anthropic و Claude Code**: دارای endpoint بومی `/v1/messages` همراه با ترجمه استریم SSE، سیستم پرامپت‌ها و فراخوانی ابزارها (tool-calling).
- **📊 داشبورد گرافیکی سه‌بعدی و زنده**: طراحی‌شده بر اساس تم شیشه‌ای تاریک (Glassmorphism)، نمایشگر سه‌بعدی زنده ارتباطات، لاگ سیستم و بخش تنظیمات پیشرفته.
- **🛡️ امنیت و محافظت از کلیدها**: ذخیره‌سازی کلیدها به‌صورت خام در فایل محلی `settings.json` (که در Git نادیده گرفته می‌شود) و ارسال ماسک‌شده (`...`) به داشبورد وب جهت امنیت اطلاعات.
- **🚀 نصب و اجرای تک‌دستوره**: فرآیند نصب سریع و خودکار برای لینوکس (`bash`)، ویندوز (`PowerShell`)، داکر و سرویس systemd.

## 📦 راهنمای راه‌اندازی سریع

### ۱. لینوکس و مک (نصب و به‌روزرسانی تک‌دستوره)

```bash
curl -sL https://raw.githubusercontent.com/sajjadgazergar-work/ip-relay/main/install.sh | bash
```

> **نکته**: با اجرای مجدد دستور بالا، کدهای رله به آخرین نسخه در شاخه `main` به‌روزرسانی می‌شوند، بدون آنکه فایل‌های پیکربندی `.env` یا `settings.json` شما بازنویسی یا پاک شوند.

**گزینه‌های نصب شخصی‌سازی‌شده:**
```bash
# نصب در یک دایرکتوری دلخواه
curl -sL ...install.sh | bash -s -- --dir /opt/ip-relay

# اجرای دستی (بدون پیکربندی سرویس systemd)
curl -sL ...install.sh | bash -s -- --manual

# استقرار در بستر کانتینر داکر
curl -sL ...install.sh | bash -s -- --docker
```

### ۲. ویندوز (PowerShell)

دستور زیر را در ترمینال PowerShell (بدون نیاز به دسترسی Administrator) اجرا کنید:

```powershell
iex (irm https://raw.githubusercontent.com/sajjadgazergar-work/ip-relay/main/install.ps1)
```

> **نکته**: در محیط PowerShell از دستور `curl` استفاده نکنید زیرا به `Invoke-WebRequest` ارجاع داده می‌شود. همیشه از فرمول `irm` بالا استفاده کنید.

### ۳. داکر (به‌صورت دستی)

```bash
docker run -d \
  --name ip-relay \
  -p 8080:8080 \
  -e PORT=8080 \
  -e UPSTREAM_BASE_URL="https://opencode.ai/zen/v1" \
  ghcr.io/sajjadgazergar-work/ip-relay:latest
```

### ۴. اجرا از سورس کلاود

```bash
git clone https://github.com/sajjadgazergar-work/ip-relay.git
cd ip-relay
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn ip_relay:app --host 0.0.0.0 --port 8080
```

داشبورد وب در آدرس **http://localhost:8080** (یا آدرس IP سرور شما) در دسترس است.

## 🔌 اتصال برنامه‌های هوش مصنوعی

کلاینت یا SDK برنامه خود را به آدرس رله هدایت کنید:

```
Base URL:  http://<server-ip>:8080/v1
API Key:   (کلید RELAY_API_KEY سرور شما، یا خالی در صورت عدم تعریف)
Model:     deepseek-v4-flash-free (یا هر شناسه مدل معتبر در سرویس بالادست)
```

### مثال: دستور curl (فرمت OpenAI)
```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer public" \
  -d '{
    "model": "deepseek-v4-flash-free",
    "messages": [{"role": "user", "content": "Hello world!"}]
  }'
```

### مثال: ابزار Claude Code CLI
```bash
export ANTHROPIC_BASE_URL="http://localhost:8080/v1"
export ANTHROPIC_AUTH_TOKEN="public"
claude
```

### مثال: کتابخانه OpenAI SDK در پایتون
```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="public"
)

response = client.chat.completions.create(
    model="deepseek-v4-flash-free",
    messages=[{"role": "user", "content": "Explain relativity briefly."}]
)
print(response.choices[0].message.content)
```

## ⚙️ جدول متغیرهای پیکربندی

تنظیمات رله از طریق متغیرهای محیطی یا داشبورد وب (که فایل محلی `settings.json` را به‌روزرسانی می‌کند) قابل پیکربندی است:

| متغیر محیطی | مقدار پیش‌فرض | توضیحات |
|---|---|---|
| `UPSTREAM_BASE_URL` | `https://opencode.ai/zen/v1` | آدرس مبدا API بالادست سازگار با OpenAI |
| `UPSTREAM_API_KEY` | `public` | کلید احراز هویت ارسال‌شده به سرور بالادست |
| `RELAY_API_KEY` | *(خالی)* | کلید اختیاری برای محافظت از رله و داشبورد وب شما |
| `PROBE_MODEL` | `deepseek-v4-flash-free` | شناسه مدلی که برای بررسی سلامت پروکسی‌ها استفاده می‌شود |
| `PROXY_POOL_TARGET` | `30` | تعداد کانال‌های پروکسی سالم خروجی که زنده نگه‌داشته می‌شوند |
| `PROXY_MAX_CANDIDATES` | `3000` | سقف تعداد کاندیداهای پروکسی صف‌آرایی شده در صف انتظار |
| `PROXY_TEST_CONCURRENCY` | `60` | تعداد کانال‌های تست موازی برای سنجش وضعیت پروکسی‌ها |
| `PROXY_PROBE_TIMEOUT` | `25` | مهلت زمان (ثانیه) برای تست اولیه زنده بودن پروکسی |
| `RELAY_PROXY_TIMEOUT` | `40` | حداکثر مهلت زمان (ثانیه) مجاز برای انحراف مسیر درخواست اصلی از پروکسی |
| `RELAY_ATTEMPTS` | `6` | سقف دفعات چرخش و تلاش مجدد روی پروکسی‌های جایگزین برای هر درخواست |
| `LANE_COOLDOWN_SEC` | `90` | زمان تعلیق (ثانیه) یک پروکسی سوخته یا لیمیت‌شده پیش از تست مجدد |
| `LANE_RECOVER_SEC` | `240` | بازه زمان (ثانیه) تست مجدد سلامت پروکسی‌های تعلیق‌شده |
| `WEBSHARE_TOKEN` | *(خالی)* | کلیدهای API اکانت‌های Webshare شما (پشتیبانی از نوشتن چند کلید خط به خط) |
| `DIRECT_LANE` | `false` | استفاده از آدرس IP اصلی خود سرور به عنوان یک کانال ارتباطی |
| `ALLOW_SOCKS` | `true` | فعال‌سازی جمع‌آوری و استفاده از پروکسی‌های SOCKS4 و SOCKS5 |
| `PORT` | `8080` | پورت وب‌سرور رله |

## 🏗️ معماری سیستم و لایه تاب‌آوری خروجی (v0.6+)

```
  [ برنامه یا گیت‌وی شما ]
            │  (درخواست متناظر با API های OpenAI / Anthropic)
            ▼
┌─────────────────────────────────────────────────────────┐
│                       ip-relay                          │
│                                                         │
│   ┌─────────────────────────────────────────────────┐   │
│   │             صف کاندیداهای چند‌منبعی             │   │
│   │   (SOCKS4/5 + HTTP/S + لیست‌ها + Webshare)     │   │
│   └────────────────────────┬────────────────────────┘   │
│                            │ (سنجش‌گرهای موازی)            │
│                            ▼                            │
│   ┌─────────────────────────────────────────────────┐   │
│   │    کانال‌های دارای رتبه‌بندی زمان تاخیر و امتیاز    │   │
│   └────────────────────────┬────────────────────────┘   │
│                            │ (بازنشانی شفاف و بی‌وقفه)      │
└────────────────────────────┼────────────────────────────┘
                             │ (ارسال از IP خروجی پروکسی)
                             ▼
                 [ سرویس‌دهنده API بالادست ]
```

1. **جمع‌آوری چندمنبعی**: رله به‌طور مداوم پروکسی‌های خروجی تازه را از کانال‌های عمومی و اکانت‌های Webshare شما واکشی می‌کند.
2. **سنجش دومرحله‌ای**: کاندیداها ابتدا از نظر باز بودن پورت TCP بررسی شده و سپس با یک درخواست واقعی ۱-توکنی، سلامت ارتباطی آن‌ها تایید می‌شود.
3. **رتبه‌بندی امتیاز بر مبنای سرعت (EWMA)**: پروکسی‌ها بر اساس سابقه سرعت پاسخ‌دهی و پایداری امتیاز گرفته و کانال‌های سریع‌تر در صدر ارتباطات قرار می‌گیرند.
4. **تغییر مسیر بی‌وقفه (Failover)**: در صورت خرابی یا اتمام سهمیه پروکسی حین پاسخ‌دهی استریم یا معمولی، درخواست بلافاصله به پروکسی پرسرعت بعدی سوق داده شده و ارتباط کاربر حفظ می‌شود.
